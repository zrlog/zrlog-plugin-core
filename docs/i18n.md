# plugin-core i18n

本工程沿用 admin-web 的前后端文案分离方式，支持 `zh_CN` 和 `en_US`。

## 语言来源与接口

- 页面及 API 优先使用 `website.language`，与 admin-web 的站点语言设置一致。修改后台语言后刷新插件页即可生效。
- 独立开发环境未配置该值时，根据 `Accept-Language` 的首选语言选择英文或中文；不支持的语言回退中文。
- `GET /api/plugins`（及已有别名路由）新增 `lang`，页面内嵌的 `pluginInfo` 使用同一个 DTO。该字段为增量兼容变更，旧客户端可忽略，旧服务端未返回时新客户端回退中文。
- HTML 的 `lang`、页面标题、`Content-Language`、Ant Design locale 和日期格式使用相同语言。
- 每次请求独立设置后端语言，并在请求执行器的 `finally` 中恢复；异常、线程复用和 CallerRunsPolicy 均不得泄漏语言状态。

## 前端

所有可见界面文案在 `src/main/frontend/src/i18n/plugin.ts` 中维护。`enUS` 必须满足由 `zhCN` 推导的 `PluginI18nResource`，新增或删除 key 时 TypeScript 检查两种语言的一致性。

按页面归类（`plugins`、`runtimeScheduler`、`runtimeStates`、`runtimeNotification`、`runtimeServices` 等），跨页面稳定文案才放入 `common`。组件使用 `getRes().runtimeScheduler.save` 这类有类型检查的属性访问，不使用动态字符串 key 或硬编码文案 fallback。

插值使用 `formatText(getRes().plugins.count, {visible, total})`，两种语言必须保留相同参数。涉及翻译的选项数组应在渲染时求值，避免模块初始化时固定语言。

## 后端

只有服务端输出的消息放入 `src/main/resources/i18n/plugin_backend_*.properties`（UTF-8），使用 `PluginI18n.text("plugin.stop.success")`。参数使用 `{0}` 等 MessageFormat 占位符。

新资源需同步维护 `META-INF/native-image/com.zrlog/plugin-core/resource-config.json`；DTO 字段需同步维护 `NativeRuntimeWarmup`。

系统维护任务通过稳定 ID 在响应/展示层翻译，数据库中的任务名称和标识保持原值。插件自行提供的名称、描述、能力标签，用户输入的任务名称和历史运行诊断保留原始内容；插件业务页的国际化由各插件自行实现。

## 验证

```sh
cd src/main/frontend
yarn type-check
CI=true yarn test --watchAll=false --runInBand
yarn build
# 工程根目录
./mvnw test
git diff --check
```

测试覆盖双语资源和插值参数、语言回退、后台设置变更、请求语言隔离，以及系统任务翻译不修改原始数据。
